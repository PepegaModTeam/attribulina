# NFS-VltEd 4.6's names for the parts of World's betas (PC) values: the words nfsms
# scripts write after the field (update_field pursuitlevels x Roadblock_CopTypes[0]
# Value 2). doc/nfsms.md. Written by scripts/nfsms/gen_words.py; rerun it rather
# than editing by hand.
#
# Read from the NFS-VltEd decompilation (NFS-VltEd/). A/_0007_0014.cs registers one
# C# class per AttribSys type and game, keyed by StringHash32 of the type name; each
# class names its properties with an attribute and reads them in order, which gives
# each name its offset in the PC files NFS-VltEd reads. The path after the offset
# names the member of our schema (data/schema/world_pc.txt) at those bytes, so a
# word finds its member by name on a platform whose layout differs (4-byte bools
# move later members). A World's betas type not listed here gets NFS-VltEd's raw
# class: its one property is Data, the value's bytes in hex ("00 00 80 3F").
#
# NFS-VltEd's WB is World's betas, the 2009 and 2010 builds here, which the editor
# reads with the final build's schema (data/schema/world_pc.txt): the paths name its
# members. A script for WB runs on a beta's files, one for W on the final build's.
#
# game <code>
# type <AttribSys type name>      Attrib::StringKey(MODEL): a StringKey field named MODEL
#   single                        one property: NFS-VltEd ignores the word after the field
#   <word> <offset> [<path>] [list <element words>]
# end
#
# <path>: member names joined with ".", [i] for an element of an inline array, down
# to the member the word sets (Reaction.mClassKey, ValueMin[1]). A word over several
# members has the deepest member holding them all (X for X.mArray and X.mLength). A
# path ending in +N: the word's bytes start N bytes into that member. No path: the
# word's members have nothing in common but the value itself, or the type has no
# struct in our schema (enums, vectors, simple values), where the offset is the same
# on every platform.
#
# The comments give where each class was read and how sure the game assignment is:
# "read" means registered for World's betas or for every game, or in a compiled
# array whose bytes other code shows; "inferred" and "uncertain" mean the game list
# is a compiled array the decompilation lacks, so it was worked out (see the comment
# and scripts/nfsms/registry.py). After a word, "# x" lists our schema's members at
# its bytes where the path doesn't name them all. "# not on <platform>" marks a word
# that can't be found that way in that platform's schema, or a type its files lack;
# "# on <platform>" a type laid out otherwise there whose words all find their
# members.
